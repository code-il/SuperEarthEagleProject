# DEVELOPMENT PROMPT 4: ASTRONOMICAL SOURCE ANALYSIS AND DISCOVERY ENGINE

You are responsible for developing the scientific analysis subsystem of SPHEREx Explorer.

Your objective is to help users identify objects that move, change brightness or exhibit interesting wavelength-dependent behaviour across SPHEREx observations.

This is what distinguishes the project from a conventional astronomical image viewer.

## 1. Your objective

Develop a Python-based scientific analysis module that works with the processed observations supplied by Person 2.

The module should help identify:
- Moving objects.
- High-proper-motion stars.
- Brown dwarfs.
- Asteroids and comets.
- Variable stars.
- Transient sources.
- Objects with interesting infrared spectral characteristics.

The application must distinguish between a potential discovery and a confirmed astronomical object.

## 3. Features to implement

### A. Source detection

Use Photutils or an appropriate astronomical source-detection library.

Identify point-like sources in processed SPHEREx images.

For each source, estimate:
- Pixel coordinates.
- Celestial coordinates.
- Flux.
- Signal-to-noise ratio.
- Source significance.
- Detection quality.

Use WCS to convert pixel coordinates into RA and declination.

### B. Temporal source matching

Match detected sources between different observation epochs.

Implement a matching algorithm that:
- Identifies sources appearing in multiple images.
- Calculates their positional displacement.
- Calculates angular separation.
- Estimates angular motion per unit time.
- Accounts for positional uncertainties.
- Identifies sources with potentially significant motion.

Do not assume every positional change is real motion. Account for image registration errors, PSF effects and measurement uncertainties.

### C. Moving-object candidates

Create a candidate-ranking system.

Identify possible:
- Nearby stars with high proper motion.
- Brown dwarfs.
- Asteroids.
- Comets.
- Other moving objects.

Use observation timestamps to calculate motion.

For fast-moving objects, allow coordinate predictions at individual observation epochs using an appropriate ephemeris or proper-motion model.

Where possible, distinguish linear proper motion from non-linear apparent motion.

### D. Variable-star analysis

Measure the brightness of selected sources across observations.

Generate:
- Flux versus time.
- Magnitude versus time, where calibrated photometry permits.
- Brightness variation.
- Uncertainty estimates.
- Variability indicators.

Identify potential variable sources.

Include a warning that differing instrumental conditions, wavelengths and calibration can imitate variability.

### E. Spectral analysis

Investigate how to extract flux as a function of wavelength.

Use SPHEREx spectral data and the archive's Spectrophotometry Tool documentation.

Implement:
- Wavelength versus flux plots.
- Spectral channel selection.
- Comparison between epochs.
- Comparison between two selected objects, where data permit.

If full spectra cannot be reliably extracted within the hackathon, produce a simplified multi-channel spectral profile and document its limitations.

### F. Catalogue cross-matching

Prepare optional cross-matching with:
- Gaia DR3.
- WISE.
- SIMBAD.

Display known object associations when available.

Do not label an object as newly discovered simply because it is absent from one catalogue.

### G. Candidate classification

Produce a preliminary classification based on observable characteristics.

For example:

- Stationary source.
- High-proper-motion candidate.
- Variable source.
- Transient candidate.
- Possible solar-system object.

Include a confidence score based on defined measurable criteria, not an unexplained AI-generated percentage.
